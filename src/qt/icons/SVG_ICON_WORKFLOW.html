Redrawing the ClassBuilder tree icons as SVG

The class-tree icons date from ~2002 — small .ico raster files (16×16 / 32×32). They look soft on modern high-DPI monitors. This document is the workflow for replacing them with crisp vector (.svg) artwork.

The build already supports SVG. QtModelIcons loads qt/icons/<name>.svg in preference to the legacy res/<name>.ico — per icon. So you can modernise the set one glyph at a time: add a single .svg, rebuild, and only that icon becomes vector. Nothing else changes.

1. Where things are

WhatPath
Legacy raster icons (69 files) ClassBuilder/res/*.ico
New SVG icons go here qt/icons/<name>.svg
Index → icon mapping (what each icon means) qt/QtModelIcons.cpp — the kIconFiles[] table
Loader (svg-preferred, ico-fallback) qt/QtModelIcons.cpp — loadModelIcon()

A new SVG must use the same base name as the .ico it replaces — e.g. public_member.ico → qt/icons/public_member.svg.

2. Icon inventory — what to prioritise

The 69 .ico files in res/ split into three groups. Verified against CClassBuilderView::InitImageList and the .rc.

GroupCountUsed asPriority
A. Tree node icons61 The main tree-view image list — one per class / member / method / relation node. This is exactly the QtModelIcons set. HIGH
B. Phase / state icons6 A separate state image list, shown in front of a tree node to mark its development phase. MEDIUM
C. Application icons2 The .exe icon and the .cbz document icon. Never appear in any tree. LOW
Not .ico — out of scope here. The toolbar (Toolbar.bmp), the tree checkboxes (CheckTreeCtrlImages.bmp) and the print page-layout pictures (printportrait.bmp / printlandscape.bmp, the “number of pages” illustrations in the Sequence- and Class-Diagram dialogs) are bitmaps, not icons. They are a different job and not part of this SVG workflow.

Group A — Tree node icons (61) HIGH

These are what every tree and every ported tree dialog shows. They are systematic — redraw a few base glyphs and compose the variants. Sub-groups, by how much drawing each really needs:

Sub-groupFilesBase glyphs to draw
Document2 — file, fileselected 1 glyph (+ a selected tint)
Class & type 5 — class, externclass, inherit, type, argument ~5 glyphs
Members 3 — public/protected/private_member 1 glyph × 3 access colours
Methods, constructors, destructors 21 — {public,protected,private} × {method, constructor, destructor, inline_method, inline_constructor, inline_destructor, empty_method} 7 glyphs × 3 access colours
Groups 3 — methodgroup, membergroup, membermethodgroup ~3 glyphs
Relations 24 — single/multi × act/pas × plain / owned / static, plain / cr 2 base arrows + composable badges
Diagrams 3 — classdiagram, sequencediagram, actor ~3 glyphs

So 61 files ≈ ~22 base glyphs once colour and badge variants are factored out. The relations sub-group is the biggest count but the least unique drawing — it is one or two arrows with owned/static/collection badges layered on.

Group B — Phase / state icons (6) MEDIUM

Empty, Analysis, Design, Implementation, Test, Complete. These live in a second image list (stateImageList in InitImageList) and are drawn as a small marker in front of a tree node to show its development phase. They are not yet in QtModelIcons (it covers Group A only) — add a state-icon provider when a Qt tree needs phase display. Worth redrawing alongside Group A for a consistent tree, but lower priority than the node icons themselves.

Group C — Application icons (2) LOW

ClassBuilder.ico (IDR_MAINFRAME — the application/window icon) and ClassBuilderDoc.ico (IDR_DESIGNTYPE / IDR_DESIGNTYPE_CBZ — the .cbz document icon, also what Explorer shows for a project file). These are not tree icons. They do want crisp high-res versions for the taskbar and Explorer, but that is a separate, low-urgency task — and a Windows app/document icon stays a multi-size .ico regardless of the Qt port, so it is not part of the SVG pipeline.

Suggested order: Group A first — and within it, the member / method / class glyphs (most visible, most reused), then relations (high count, low unique effort), then diagrams. Group B next for a consistent tree. Group C last, and as .ico not SVG.

3. Build prerequisite — the qtsvg module

SVG icons need Qt's Svg module. The static Qt at C:/Qt-static is currently qtbase-only — it has no Svg module, so SVG icons are inert until that Qt is rebuilt.

One-time step: rebuild the static Qt with the qtsvg module (see Projects/qt-static/build-static-qt.bat). After that, just reconfigure:

cmake --preset x64

CMake auto-detects Qt6Svg and prints Qt: Svg module found — SVG model icons enabled. No source change is needed. Until then it prints Qt: no Svg module — model icons use the legacy .ico set and the build stays green on the .ico artwork.

4. The honest part: there is no .ico → .svg conversion

.ico is raster (pixels); .svg is vector (shapes). You cannot convert — you redraw, using the old icon as a tracing reference underneath. Auto-trace (Inkscape's “Trace Bitmap” / potrace) on a 16–32 px source produces blobby, inaccurate paths — not worth it. Treat the .ico as a reference image, not a source.

The big shortcut — the icons are systematic. As the Group A table shows, the 61 node icons collapse to ~22 base glyphs with colour and badge variants. Draw the base glyphs once, then compose. An afternoon, not a marathon.

6. Workflow (Inkscape)

  1. Install Inkscape. Optionally ImageMagick for batch frame extraction.
  2. Extract a reference PNG from the .ico — the largest frame (usually 32×32): 
    magick "ClassBuilder/res/public_member.ico[0]" ref_public_member.png
    [0] selects the first/largest frame.
  3. New Inkscape document, e.g. 48×48 or 64×64.
  4. Place the PNG as a faint, locked reference layer.
  5. Redraw the glyph above it with clean vector shapes (rectangles, circles, paths). Snap to a grid.
  6. Save As → Optimized SVG (strips editor metadata, smaller files).
  7. Name it exactly like the .ico base name and save into qt/icons/.

Drawing tips that matter at small sizes

  • Design on a pixel grid — an icon crisp at 16 px needs deliberate alignment, not just a shrunk 48 px drawing.
  • Keep shapes axis-aligned; avoid strokes thinner than 1 px.
  • Do the base glyphs first, then derive the colour/badge variants.

7. Which sizes — if you also refresh the .ico set

SVG is resolution-independent, so for the Qt side there is no size question. If you also rebuild the .ico files (for the MFC build, or Group C), bake in 16, 20, 24, 32, 48 — that covers 100–300% display scaling for a tree row. Skip 128/256: a tree never renders that big and they only bloat the file. (Group C app/document icons may justify 256 for Explorer thumbnails.)

8. Adding an icon — the loop

  1. Redraw a glyph, save qt/icons/<name>.svg.
  2. cmake --preset x64  (picks up the new file)
  3. cmake --build --preset x64-release
  4. That icon is now vector; the rest stay .ico. Repeat.
If CMake still reports no Svg module, the SVG will not render — finish the qtsvg rebuild in section 3 first.

9. Going further: SVG for the main class tree

The same QtModelIcons provider is intended for every Qt tree dialog and, eventually, the main class tree once it is ported from MFC. So a redrawn Group A set benefits the whole application, not just FindMethodDialog.
