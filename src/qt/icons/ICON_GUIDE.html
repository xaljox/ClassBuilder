ClassBuilder — Icon Guide

Where the icons live, how to modernise them to SVG one glyph at a time, and the gotchas. Everything icon-related sits under qt/icons/.

The two icon sets

Both loaders prefer a redrawn .svg from qt/icons/ over the legacy raster, so the set can be modernised incrementally — add a single .svg, rebuild, and only that icon goes vector.

Toolbar glyphs — the "new" toolbar buttons

The toolbar icons were never individual files — they live as tiles inside the one bitmap strip res/Toolbar.bmp. To give you something to trace, the strip is sliced into individual transparent PNGs in qt/icons/toolbar_src/, named by glyph:

toolbar_src/00_file_new.png   05_read_source.png   06_save_source.png
            10_edit_delete.png 21_add_note.png      22_add_lifeline.png
            24_add_class.png   30_add_argument.png  31_add_virtuals.png
            32_add_isclass.png 33_add_type.png      ...  (34 tiles)

Re-generate them any time the strip changes:

pwsh tools/slice_toolbar_bmp.ps1

To replace a toolbar glyph

Draw tb_<name>.svg in qt/icons/ — e.g. tb_add_note.svg, tb_add_lifeline.svg, tb_edit_delete.svg. QtToolBarIcons.cpp lists every <name> and the order; Qt_ToolBarIcon(TG_*) then prefers your SVG over the strip tile. The strip's mask colour is RGB(192,192,192) (made transparent on load) — your SVG just needs a transparent background.

Model / tree glyphs

Drop <name>.svg in qt/icons/ using the same base name as res/<name>.ico (e.g. public_member.svg, class.svg). QtModelIcons.cpp lists all 67 base names. The .ico files are already individual, so open them in ClassBuilder/res/ directly as references — no slicing needed.

Size

The toolbars currently render at 16 px — the native size of the legacy glyphs (scaling that raster up looks muddy). Once crisp SVGs exist, bump the size: it's one line per toolbar, setIconSize(QSize(20, 20)), in QtShellWindow.cpp, ClassDiagramQtView.cpp, SequenceDiagramQtView.cpp and MainTreeQtView.cpp (or hook them to one shared constant).

⚠ SVG module required. The overrides only take effect once this Qt build has the Svg module (CB_HAVE_SVG). The static Qt at C:/Qt-static is currently qtbase-only, so until qtsvg is added (Projects/qt-static/build-static-qt.bat), the .ico / strip tiles are used and any tb_*.svg / <name>.svg you add sit dormant — no harm, no code change. When qtsvg arrives, just reconfigure CMake. SVGs here are bundled by the qt/icons/*.svg glob in CMakeLists.txt.
✓ Incremental. Both loaders fall back to the legacy raster per glyph, so you can convert the set one icon at a time and never break the build.

Drawing tips

  • Design on a pixel grid; keep shapes axis-aligned so the 16 px render is crisp.
  • Many model icons are systematic variants (public/protected/private = one glyph in three colours; relation icons = single/multi × act/pas × owned/static/cr). Draw the few base glyphs, then compose — not 60+ unique drawings.
  • The toolbar "Add X" glyphs are typically the node glyph + a small green + badge; keep that family consistent.
  • Save as Optimized / Plain SVG.
